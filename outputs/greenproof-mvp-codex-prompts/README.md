# GreenProof 数据驱动数字孪生 MVP：Codex 开发任务包

本任务包用于开发一个可展示给剑桥学院或首个屋顶光伏业主的 MVP。它不是生产级计量或正式绿证平台，而是一个由公开真实数据驱动的多租户绿电消费数字孪生。

## MVP要证明的事情

- 公开数据可以构造具有英国和剑桥真实感的屋顶光伏与建筑负荷。
- 一个共享光伏源可以按明确规则分配给两个模拟租户。
- 每个时间区间可以计算现场消纳、购电和上网。
- 每个结果可以追溯至数据源、处理版本和分配规则。
- 演示证明可以通过哈希和 Merkle 路径验证未被修改。

## 明确不在本期范围内

- 真实电表和边缘网关；
- 正式绿证签发；
- 生产区块链、NFT或代币；
- 零知识证明和 Daml/Canton；
- 储能绿电追踪；
- 真实弃电认证；
- 生产级多租户SaaS、计费和复杂权限。

## 推荐技术栈

- 前端：React、TypeScript、Vite；
- 图表：ECharts、D3 或原生 SVG，择一；
- 数据处理：Python、Polars/Pandas、DuckDB、PyArrow；
- 数据文件：Parquet 用于处理，压缩 JSON 用于演示端；
- 哈希：SHA-256、Canonical JSON、Merkle Tree；
- 测试：Pytest、Vitest、Playwright；
- 部署：静态托管。

## 续作模块规则

产品在真实实现和审计中发现的新风险，不回写或覆盖原模块 Prompt。每个续作需求都建立新的编号目录，至少包含 `PROMPT.md` 和 `LOG.md`，并在本路线图中注明它加固的原模块。模块 11 是第一项按此规则保存的续作产品模块。

## 使用方法

1. 按编号打开模块目录中的 `PROMPT.md`。
2. 将全文复制到一个新的 Codex 任务中，并让 Codex 在同一个项目仓库工作。
3. 每次只执行一个模块；确认验收通过后再进入下一个。
4. 要求 Codex 完成后回填该模块的 `LOG.md`。
5. 如果数据下载受限，必须实现缓存、fixture 和明确的回退路径，不得静默捏造数据。

## 全局工程规则

- 所有时间序列内部统一为 UTC，界面可显示 `Europe/London`。
- 所有电量使用整数 Wh，功率使用 W。
- 比较粒度等于参与数据源中最粗的真实粒度；不得把插值值标为实测。
- 每个值必须携带 `provenance` 和 `quality_flags`。
- 每个外部数据集必须记录来源URL、版本、许可证、下载时间和原文件哈希。
- 实测、模型、缩放、聚合、插值、外推必须清楚区分。
- 所有分配结果必须满足能量守恒和不可重复分配。
- 页面必须显著显示“演示/模拟认证，不是正式绿证”。
- 不提交大型原始数据到Git；保存下载脚本、数据清单和小型fixture。

## 统一完成定义

每个模块只有在以下条件全部满足时才算完成：

- 功能代码已实现；
- 自动化测试通过；
- 数据或算法来源有文档；
- 失败和回退路径经过测试；
- 没有把估算值伪装为实测值；
- 对应 `LOG.md` 已填写；
- README或开发文档已更新。
