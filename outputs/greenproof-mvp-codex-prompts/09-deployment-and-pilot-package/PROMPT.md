# Codex任务：09 部署与Pilot演示包

请将经过测试的GreenProof MVP整理为可分享给剑桥学院或首个屋顶光伏业主的演示版本。

## 任务目标

1. 创建生产构建配置，但保持MVP为静态或最小服务部署。
2. 选择适合现有仓库的静态托管方式；不要未经授权购买域名或创建收费资源。
3. 确保所有公开数据快照随构建发布，页面不依赖外部数据源实时在线。
4. 提供环境变量示例，但不得提交密钥。
5. 配置：
   - 缓存策略；
   - 内容安全策略；
   - 基本安全响应头；
   - 404和损坏场景页面；
   - 可选匿名错误监控，默认不采集细粒度用户数据。
6. 编写3分钟演示脚本：
   - 介绍数据来源；
   - 展示一个光伏服务两个租户；
   - 拖动一天时间；
   - 切换分配规则；
   - 查看期间汇总；
   - 查看Evidence和验证证明；
   - 明确这是公开数据演示。
7. 编写Pilot问题清单：
   - 对方真实数据的格式、粒度、时间范围；
   - 光伏与负荷的资产边界；
   - 是否存在多个租户；
   - 希望采用什么分配规则；
   - 愿意公开哪些字段；
   - 最希望证明什么业务事实；
   - 是否愿意进入下一阶段试点。
8. 创建数据替换指南，说明未来如何用客户CSV替换：
   - 光伏；
   - Tenant A；
   - Tenant B；
   而不修改前端和匹配引擎。
9. 生成一个可打印的演示证明页面；不要假装是正式证书。
10. 在README中提供本地运行、构建、预览和部署步骤。

## 发布前检查

- 所有第三方数据具有正确引用；
- 不分发许可证不允许重新分发的原始数据；
- 页面无精确匿名建筑身份泄露；
- 演示免责声明可见；
- 所有链接有效；
- 移动端和主流浏览器测试通过；
- 数据源不可用不会影响已发布演示；
- 证明验证可离线运行。

## 成功指标

将以下反馈收集项加入演示后问卷：

- 用户能否正确解释“发电、现场消纳、上网”；
- 用户是否理解两个租户的分配规则；
- 用户是否信任数据来源说明；
- 用户是否认为这类证明有价值；
- 用户是否愿意提供真实半小时/小时数据；
- 用户愿意支付、共同开发或引荐的意愿；
- 哪些页面或概念最难理解。

## 验收标准

- 一个命令可构建发布版本。
- 演示链接或本地预览在无外部API时完整运行。
- 有清晰的演示脚本、数据替换指南和反馈模板。
- 所有测试仍通过。
- 没有超出MVP范围的账户、支付、交易或区块链功能。

## 完成后

更新本模块 `LOG.md`，记录部署方式、版本、构建哈希、演示URL（如经授权部署）、测试结果、已知限制和Pilot反馈安排。
